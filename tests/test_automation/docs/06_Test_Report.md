## 4 Anomalies (defects / observations)

### ANOMALY-001 - After adding or editing a colour in the legend, the editor has no keyboard focus

| Found by | Severity | Risk | Status |
|---|---|---|---|
| TC-LEG-002 (Behave + pytest-bdd run with the real colour dialog) | Low (usability) | None for data integrity | Open - waiting for decision (the product owner asked not to change the application in this task) |

**Steps:** 1. Open a tree. 2. Legend > '+ Add colour', enter a meaning, OK. 3. Type a letter / press the new colour shortcut without clicking into the text.  
**Expected:** The cursor is back in the text editor, as before the dialog.  
**Actual:** No widget has the keyboard focus (the '+ Add colour' button that had it is re-created when the legend is rebuilt). Typed text goes nowhere until the user clicks into the editor; window shortcuts still work when the window is active. No data is lost or changed.  
**Proposal:** Give the focus back to the editor after legend actions.

### ANOMALY-002 - Duplicate + Delete of a branch with an empty line above leaves one extra empty line

| Found by | Severity | Risk | Status |
|---|---|---|---|
| TC-EDIT-003 (pytest system test) | Low (cosmetic) | None (no names or explanations change; Ctrl+Z restores) | Open - requirement clarification needed |

**Steps:** 1. Open tree_a.txt (empty line 2 above 'src/'). 2. Cursor on 'src/', Ctrl+D. 3. Ctrl+Shift+Delete on the copy.  
**Expected:** Not specified by the requirements (REQ-EDIT-005 / REQ-EDIT-006).  
**Actual:** Ctrl+D copies the empty line above the branch together with the branch. Deleting the copy keeps its empty line (delete never removes spacing), so one '│' line more than before remains above 'docs/'.  
**Proposal:** Clarify the wanted behaviour (copy the empty line or not) and add it to REQ-EDIT-005.

### ANOMALY-003 - Zoom of the item picture was reset whenever the tree text was re-read

| Found by | Severity | Risk | Status |
|---|---|---|---|
| PictureTests::test_zoom_in_out_fit_and_limits (developer GUI test, Nodeon 1.1.0 development) | Medium (usability) | None for data integrity | Closed - fixed in 1.1.0 and verified by TC-ITEM-005 |

**Steps:** 1. Item with a big picture. 2. Zoom in. 3. Wait for the editor to re-read the text (e.g. after the cursor moves within the same item).  
**Expected:** The zoom stays as chosen.  
**Actual:** The picture was loaded again and fitted to the panel (zoom lost).  
**Proposal:** Load the picture only when another picture is shown.

### ANOMALY-004 - Undo of "Delete line" or of a move to another place lost pictures of the affected rows

| Found by | Severity | Risk | Status |
|---|---|---|---|
| FollowTheRowTests + StressTests (random editing, Undo of everything, 6 seeds) | High (data shown on the wrong row / not shown) | High for data integrity before the fix (nothing was deleted from disk) | Closed - fixed in 1.1.0; verified by TC-ITEM-012 (also 40 seeds x 150 random steps) |

**Steps:** 1. Give the children of a branch pictures. 2. Ctrl+Q on the branch (children move up a level). 3. Ctrl+Z.  
**Expected:** The children have their pictures and features again.  
**Actual:** The rows came back but without their pictures, because the line-by-line comparison could not match rows whose position and level changed at the same time. One redo sequence even showed a neighbour's features on a row.  
**Proposal:** Remember which row key held which details for every text state seen; Undo / Redo return to a known text and restore the exact assignment. Rows still unmatched are paired by their own name when it is unique.


### ANOMALY-005 - Alt+letter typed the letter into a feature box
